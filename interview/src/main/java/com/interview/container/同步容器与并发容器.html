同步容器与并发容器

包路径：com.interview.container — 面试复习专用

一、同步容器 Synchronized

对应源文件：SynchronizedContainers.java

核心机制

全局锁。几乎所有方法都用 synchronized 修饰，锁住当前对象实例。

常见类型

  • Vector、Hashtable（JDK 遗留类）
  • Collections.synchronizedList()、synchronizedSet()、synchronizedMap() 包装出的同步视图

具体表现

  1. 读写全串行——读操作也需要获取锁，读多写少场景下性能严重下降。
  2. 复合操作非原子——迭代、put-if-absent、先检查后执行等组合操作仍需外部同步，否则可能抛出 ConcurrentModificationException。
  3. 迭代器 fail-fast——迭代期间若其他线程修改了集合，立即抛出 ConcurrentModificationException，而非继续遍历脏数据。
📌 典型坑点： 迭代器遍历时必须手动 synchronized(collection) { for (...) }， 否则多线程环境下必现 ConcurrentModificationException。

二、并发容器 Concurrent

对应源文件：ConcurrentHashMapDemo.java、 CopyOnWriteDemo.java

核心机制

细粒度锁 + CAS（Compare-And-Swap）无锁算法 + 分段 / 桶锁，取代单一的全局锁。

常见类型

ConcurrentHashMap 分段哈希表

JDK 版本实现策略
JDK 7Segment 数组，每段继承 ReentrantLock，锁住一段哈希桶
JDK 8+CAS + synchronized 只锁链表 / 红黑树头节点，读操作几乎完全无锁
  • 写操作只锁对应的桶，不影响其他桶的读写
  • 提供了 putIfAbsent、compute 等原子复合方法
  • 迭代器是弱一致性的：遍历不抛异常，但可能看不到迭代开始后的修改

CopyOnWriteArrayList / CopyOnWriteArraySet 写时复制

  • 修改操作（add、set、remove）用 ReentrantLock 保证单线程复制整个底层数组
  • 读完全无锁，永不阻塞，性能极高
  • 迭代器是快照风格的：迭代器创建后，其他线程的修改不会影响当前遍历
  • 适合读多写极少的场景；写频繁时复制成本高、内存占用大

ConcurrentLinkedQueue 无锁队列

  • 基于 CAS 的无锁非阻塞队列（Michael-Scott 算法）
  • 无锁化高并发，适合多生产者、多消费者场景

BlockingQueue 系列 阻塞队列

如 ArrayBlockingQueue、LinkedBlockingQueue、SynchronousQueue 等：

  • 结合 ReentrantLock + Condition 实现阻塞的生产者-消费者模式
  • put() 满时阻塞，take() 空时阻塞

具体表现

  1. 读写并发度高——读多写少和并发写入场景下远优于同步容器。
  2. 弱一致性迭代器（fail-safe）——遍历过程中其他线程的修改不会被看到，但也不抛异常。 准确地说，ConcurrentHashMap 的迭代器反映迭代开始时的状态或其后的部分状态； CopyOnWriteArrayList 的迭代器则是创建时刻的数组快照。
  3. size() / isEmpty() 语义减弱——这些方法的返回值在并发环境下是近似值，不保证实时精确。
📌 面试常问： "ConcurrentHashMap 如何保证线程安全？" → JDK 8 的回答思路：
  1. 数组初始化用 CAS（避免多次初始化）；
  2. put 时对应桶为空 → CAS 直接插入；
  3. 桶非空 → synchronized 锁住头节点后再操作链表/红黑树；
  4. 扩容时多线程协同（transfer 方法支持并发迁移）。

三、对比总结

维度 同步容器 并发容器
锁粒度 全局锁（整个对象） 分段 / 桶锁 或 CAS 无锁
读并发 串行（也需要锁） 几乎无锁，极高并发
写并发 串行 只锁对应分片
迭代器风格 fail-fast（快速失败，抛异常） fail-safe / 弱一致性（不抛异常）
复合操作 需外部手动加锁 提供原子复合方法（如 putIfAbsent）
适用场景 低频访问或完全串行无妨 高并发读写
